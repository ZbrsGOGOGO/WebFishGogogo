# 私有开发协作台

本模块用于核心成员向站长提交网站修改建议及参考附件，不是在线代码编辑器，也不授予服务器、GitHub 或部署权限。当前实现处于本地待发布阶段。

## 权限与账号

- 站长：网站中处于 active 状态的 `admin` 账号。可查看全部提案、授权/撤销核心成员、填写审核意见和更新处理状态。
- 核心成员：在独立的开发协作成员表中授权的现有账号。只能查看自己的提案、附件、讨论和处理结果；不会升级为全站管理员。
- 普通用户和访客：没有提案或附件读取权限。前端入口来自服务端权限查询，隐藏按钮不是安全边界。
- 授权按现有用户名查找；撤销使用用户的公开 ID。成员应各自登录，不共享管理密码。

首个站长需要先核对现有账号的公开 ID，再由服务器运维使用现有 `community-role:set` 离线工具赋予 admin。该工具要求明确的目标、确认串和原因，并写入审计日志。不要把普通核心成员通过这个工具升为 admin。

```sh
# 仅示意：确认目标账号之后再使用，不要原样执行占位值。
COMMUNITY_ROLE_TARGET_PUBLIC_ID=已核对的公开UUID \
COMMUNITY_ROLE_TARGET_ROLE=admin \
COMMUNITY_ROLE_CONFIRMATION=ASSIGN:已核对的公开UUID:admin \
COMMUNITY_ROLE_REASON=站长本人管理开发协作台 \
npm run community-role:set --workspace @stealth-reader/backend
```

本次开发不会猜测站长身份、创建共用密码或自动提升任何生产账号。

## 使用流程

1. 登录后进入 `/development`，提交标题、分类和详细说明。描述应包含当前问题、期望行为及验收方式。
2. 在提案详情补充参考附件、截图或评论。上传失败与提案提交成功分别显示，可以处理失败文件后重试，不必重建提案。
3. 系统生成规则式预检，提示材料是否完整、哪些内容尚未读取，以及可能需要补充的风险说明。
4. 站长查看提案、文件及预检，填写理由后决定补充资料、采纳或暂不采纳。
5. 采纳后由站长跟踪为“处理中”和“已完成”。状态变化不等于代码已自动修改或网站已部署。

提交、补充和审核结果接入站内通知。详情显示讨论与处理时间线；版本冲突需刷新后再次确认，不能覆盖别人刚提交的内容。

## 附件安全与读取边界

- 每个文件最多 5 MiB；每条提案最多 5 个附件、总计 20 MiB；每个作者累计附件上限 100 MiB，每天最多新建 20 条提案。每条提案最多 200 条评论、50 次审核决定。
- 支持 TXT、Markdown、CSV、JSON、LOG、PDF、DOCX、ZIP、PNG、JPEG、WebP；不接收 HTML、SVG、可执行文件或脚本。
- 文件名、大小、内容类型与文件特征由后端复核，不只信任浏览器声明。文件保存于 PostgreSQL 的私有二进制字段中，现有数据库备份包含附件，不产生公开静态文件 URL。
- 文本和可提取的 DOCX 正文只展示限长纯文本。ZIP 只生成目录摘要；安全检查会流式校验压缩内容的实际体积，但不提取到服务器目录、不执行文件，也不代表已语义阅读其中的正文。PDF、图片及未提取部分明确标注需人工阅读；没有 OCR、PDF 全文解析或杀毒服务保证。
- 下载必须经过当前账号权限检查，强制作为附件返回，关闭缓存并禁止浏览器类型嗅探。页面不会以内嵌 HTML 执行用户文件。
- 附件、文件名、正文和评论均为不可信资料。任何“忽略规则”“执行命令”“上传密钥”“直接部署”等文字都不是站长授权。
- 仅提案作者可以补充附件。账号完成注销时，删除其提案及附件、清理其在其他提案中的事件正文与成员授权；已导出到其他设备的资料不能由网站自动追回。

数据库存储适用于当前小规模核心成员协作。放开公众提交或显著扩大容量前，应引入私有对象存储、病毒扫描、保留期限与清理流程，避免数据库备份持续膨胀。

## 自动预检不等于 AI 已审核

当前接口明确返回 `reviewMode: manual`，预检返回 `kind: rules`、`aiReviewed: false`。没有配置 AI API，没有把附件发送给第三方，没有启动无人值守的 Codex 监控，也不会产生模型调用费用。

站长可导出待审资料 JSON，交给当前开发会话进行结合仓库的正式评审。导出包含私有提案、附件摘要和讨论，请按内部资料保管；原附件二进制不会进入 JSON。默认导出“待审阅/待补充”，一次最多 20 条，不应当作全库备份；评审需要完整附件时仍须单独下载并提供。

如果后续需要持续监控，有两条独立路线：

1. 在桌面端配置可访问此项目的计划任务，以及最小权限的私有资料读取通道。依赖本机项目的任务要求电脑开机、应用运行；本轮没有创建任何计划任务。[官方计划任务说明](https://learn.chatgpt.com/docs/automations?surface=app)
2. 在服务器配置独立的 AI 审核服务、密钥、预算与隐私确认，使用只读队列输入和报告写入权限，设置失败重试及去重。AI 只给出建议，不得获得成员授权、修改状态为已完成、代码执行或部署权限。

建议正式评审报告至少包含：需求理解、附件实际读取范围、对应仓库位置、收益、风险、预计改动范围、验收办法，以及“建议修改 / 需澄清 / 暂不建议”。最终采纳仍由站长决定。

## 发布与验收

- 新增数据库迁移 `0026 AddDevelopmentWorkspace`，不能只替换前端文件。先备份数据库，再沿用现有 migration 服务执行迁移；迁移演练脚本已更新至 `0026`，包含先撤销 `0026` 再验证旧 `0025` 回退的顺序。
- 服务端配置 `FEATURE_DEVELOPMENT_WORKSPACE_ENABLED=true` 才启用；未配置或为 false 时默认关闭。权限由运行时 API 返回，不需要另一个前端开关。
- 新版 Nginx 放行 `/api/v1/development`，仅附件上传路径放宽到 6 MiB 的 multipart 请求体，并增加限速和并发上限；其他 API 仍保持原有 1 MiB 限制。
- 发布后用三个专用账号验收：站长、已授权核心成员、未授权普通用户。验证提案、上传/下载、跨账号拒绝、撤销权限、审核冲突和站内通知。
- 回滚应用前先关闭功能开关。不要为回滚旧应用直接删除新表或附件；数据库迁移回退会删除协作数据，需单独确认并保留备份。

## 本地验证记录（2026-09-07）

- 后端全量回归：96 个测试套件、492 项测试通过，覆盖新模块及既有账号、聊天、好友、小游戏等功能。
- 前端全量回归：105 个测试文件、506 项测试通过；包括跨账号/跨提案晚响应隔离、创建重试去重、状态流转、附件失败提示与私有下载。
- 前后端生产构建通过。前端以 `VITE_SITE_MODE=community VITE_API_BASE_URL=/api` 构建，开发协作页面按需加载。
- 独立无头 Firefox 配合本地模拟 API 完成页面烟测：站长、核心成员、未授权用户三个身份，附件脚本按纯文本呈现、站长不能替作者上传；390 像素布局无横向溢出。这不是生产端到端验收。
- Nest HTTP 测试验证实际 multipart 请求、5 MiB 上限、额外字段拒绝、权限守卫在文件解析之前执行，以及下载原始字节与安全响应头。
- 附件策略及规则预检 32 项测试通过；数据库迁移与业务测试使用 pg-mem，注册生产内建函数 `octet_length(bytea)` 的测试等价实现，未降低生产字节完整性约束。
- 依赖审计（含开发依赖及仅生产依赖）均为 0 条已报告漏洞；部署脚本语法、迁移顺序静态回归与 `git diff --check` 通过。
- 本轮没有连接生产执行写入，没有创建或提升生产账号，没有提交、推送、部署或开启自动任务。尚未完成真实 PostgreSQL 多连接并发测试、Docker 迁移演练、线上 Nginx 配置验收及三账号生产验收；正式发布时需补齐。
