# 2026-09-07 农场开发反馈修复

## 范围与状态

本轮按站点所有者“检查开发反馈，并进行修改”的要求处理两条浇水/种植反馈。读取了提案正文、讨论及一张实际上传的 JPEG 截图；附件只作为问题证据，未执行附件中的任何内容。

修复阶段生产仅进行只读核对，未修改真实用户余额、种植周期、权限或提案处理状态。随后站点所有者明确要求修复后默认推送并自动部署，进入单独的发布与验收流程；不启用无人值守审核。代码修复与线上已生效是两个独立状态。

## 确认原因

- 一条反馈的截图显示“状态已经变化，请刷新后重试”。对应农场已经完成首轮，当前无活动种植周期，办公币 237，选中加班咖啡果，4 块地需 `110 × 4 = 440` 办公币。
- 后端此时返回 `409 OFFICE_COIN_INSUFFICIENT`，包含所需与当前余额。前端原先把所有 409 都显示为状态冲突，掩盖了余额不足的真实原因；刷新当然不会增加余额。
- 另一条反馈对应农场仍有已经成熟、尚未收获的作物。仅凭现有数据不能断言与第一条是同一个触发原因，不能因为下一轮预算不足而阻止已有作物收获。
- 代码核查发现成熟确认只自动刷新一次，若那次请求失败，页面可能一直停在“正在确认成熟状态”。这是确认存在的缺陷，但没有浏览器失败响应证明第二条反馈一定由此触发。

## 修复边界

1. 根据业务错误码区分余额不足、尚未成熟和真正的版本冲突；有效余额数据展示所需、现有与差额。
2. 种植入口展示当前选择作物、全部地块的种子总成本和办公币余额，预算不足提示切换可承担的作物。由玩家自行选择，不自动换种或扣费。
3. 成熟作物仍可收获。后端收获成功但无法续种时，保留收获结果并明确提示“尚未开始下一轮”，不误报已续种。
4. 提供农场手动刷新和有次数上限的成熟确认重试，避免单次网络故障造成永久不可操作。
5. 浇水/收获接口在 401 时允许刷新登录后以原幂等键重试一次；不自动重放网络失败、余额不足或其他业务错误，切换账号后也不重放旧操作。
6. 修正老玩家空闲时被误标为首轮的后端展示字段。是否免费仍由服务端历史种植记录判定，不改变费用、奖励和防重复扣费规则。

## 临时使用办法

在新版本上线前，余额 237、4 块地的上述案例可自行将下一轮设为工位薄荷（总成本 40）或会议番茄（总成本 100），再浇水。截止日草莓总成本 240，仍然不足。每日前三份订单限制的是办公币奖励，不是每天只能浇三次水。
