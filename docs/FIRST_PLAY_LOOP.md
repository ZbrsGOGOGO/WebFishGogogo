# 首玩闭环设计与修改方案

## 1. 产品判断

当前版本已经具备阅读、工具、农场和小游戏四套可用系统，适合做小范围体验；但初次进入时四个入口权重相同，用户不知道“先做什么”，而农场最短 30 分钟才有反馈，首局很难形成继续玩的理由。

本轮把产品主张收敛为：

> 上班族轻量工作台：工作时用阅读和工具积累成长，空闲时收菜或玩一局。

初版不继续增加游戏数量，先让注册后的第一次会话产生一次明确的投入、等待、收获和解锁。

## 2. 首玩目标

新用户在三分钟内看懂并完成下面的闭环：

1. 每日签到，领取 5 水滴。
2. 进入农场，一键选中第一块地和工位小麦。
3. 第一次种植自动压缩为 30 秒。
4. 收获基础奖励和 40 农场 EXP 新人加成。
5. 农场经验达到 50，升至 Lv.2，立即解锁加班咖啡豆。
6. 返回首页看到签到、首收已经完成，并被引导去玩一局小游戏。

## 3. 规则方案

### 新手状态

不新增数据库字段，直接根据保留的 `farm_plantings` 历史推导：

- 没有任何种植历史：`choose_plot`，首次加速可用。
- 有未成熟种植：`growing`。
- 有成熟未收获种植：`ready`。
- 至少有一条已收获记录：`completed`。

这种方案能兼容现有用户和现有数据库，不需要迁移；旧玩家只要已有收获记录，就不会再次获得新人加速或新人经验。

### 数值

| 项目 | 规则 |
| --- | --- |
| 首次种植时长 | `min(作物原时长, 30 秒)` |
| 首次收获加成 | 额外 `40` 农场 EXP |
| 小麦首次收获结果 | 基础 `10` + 新人 `40` = `50` 农场 EXP |
| 首个解锁 | 农场 Lv.2 解锁加班咖啡豆 |
| 后续种植 | 完全恢复原作物时长和原奖励 |

种植与收获仍使用原有事务、用户级锁、幂等键、资产流水和 Outbox 事件；新人加成只在首次收获事务中计算，不会因重试重复发放。

## 4. 页面设计

### 首页

- Hero 从“单机版已就绪”改为“3 分钟开局 / 30 秒首收 / Lv.2 解锁咖啡”。
- 把“今日摸鱼路线”放在四个系统入口之前，形成签到、首收、小游戏三步路线。
- 路线读取真实签到与农场状态，完成后显示勾选和下一步动作。
- 增加等级目标阶梯：农场 Lv.2 咖啡、全站 Lv.3 斗技场、农场 Lv.5 第五块地。
- 农场初始化完成后主动刷新一次平台资产，避免新手礼包已到账而水滴仍短暂显示为 0。

### 农场

- 未完成首收时展示高优先级新手任务卡，内容随 `choose_plot / growing / ready` 切换。
- “选好小麦，开始首种”同时选中第一块空地与小麦，减少操作成本。
- 作物卡在首次种植前明确显示“本次新手加速：30 秒”。
- 倒计时归零后，任务卡无需请求服务器即可同步切换为“马上收获”。
- 首收完成展示升级与咖啡解锁庆祝；咖啡作物立即可选。

## 6. 验收标准与结果

- 新账号能获得 4 水滴新手包，签到后总水滴为 9。
- 首次小麦种植扣除后为 8 水滴、3 颗小麦种子，倒计时为 30 秒。
- 30 秒后可收获，农场从 Lv.1 / 0 EXP 变为 Lv.2 / 50 EXP。
- 收获返还小麦种子，办公币增加 5，咖啡作物解除等级锁定。
- 回到首页后签到与首收步骤都显示完成。
- 第二次小麦种植恢复为 30 分钟，首次奖励不重复。

## 7. 下一轮建议

按优先级继续做：

1. 记录“首次看到路线、开始首种、完成首收、完成首局”漏斗事件，观察注册到首收完成率。
2. 给小游戏补统一的首局完成记录、个人最高分和每日挑战，使首页第三步也能真实完成。
3. 用连续三天任务和农场订单建立第二天回访理由，再考虑扩作物或增加新游戏。

建议首轮重点指标：注册到首种转化率、注册到首收完成率、首收后进入小游戏比例、次日回访率。
