# 2026-09-07 账号、聊天与小游戏检查

检查基线：`feat/workstation-tower-defense` / `c362c2d`。本轮检查覆盖账号登录与会话、好友关系、公共聊天室、私聊、小游戏成绩接入和依赖；线上只做无凭据的健康与响应头检查。结论适用于本次检查范围，不等同于完整渗透测试。

## 确认的问题与处理

| 问题 | 影响 | 本轮处理 |
| --- | --- | --- |
| 登录校验与改密之间的竞态 | 旧密码先通过校验、改密随后提交时，旧请求仍可能在全部会话撤销后创建新会话 | 锁定账号后复核密码哈希是否变化，必要时重新验证最新哈希；覆盖邮箱与用户名登录 |
| 公共聊天室切换时旧状态及请求未隔离 | 旧房间消息可能混入当前页面，失败消息的重试可能指向新房间 | 房间状态与请求生命周期隔离，安全处理断线和发送状态 |
| 会话请求跨越退出或账号切换 | 旧恢复结果可能覆盖新状态，旧退出响应可能清除新令牌，旧 GET 可能用新账号重试或将旧账号数据交给新页面 | 显式会话版本隔离、请求归属检查，丢弃跨账号的过期读取响应；退出请求发出后立即清理本地状态 |
| 私聊发送隐式清空未读 | 自己发送消息会把尚未阅读的对方消息标成已读，未读数与回执不一致 | 已读游标由明确的已读操作推进 |
| 好友查找结果过期 | 快速修改账号或发起新查询后，旧请求可能显示错误的申请对象 | 修改输入立即收起旧结果，过期响应和关系刷新不覆盖新搜索 |
| WebSocket 认证与关闭竞态 | 已关闭连接可能在认证返回后重新占用用户连接名额 | 认证返回时复核连接生命周期 |
| 延迟私聊已读事件缺少再次授权 | 拉黑后的排队事件或错误的内部事件可能暴露会话编号与已读序号 | 广播前重新查询当前参与者与拉黑状态，并核对接收人集合 |
| 小游戏异步请求跨局污染 | 连续重开或退出后，旧开局/结算请求可能覆盖新局提示或继续提交 | 每局使用独立请求上下文，开局请求依序发送，忽略过期结果与重复结算 |
| 小游戏服务端并发开局/首次最佳分竞争 | 两次事务可能同时创建有效局，首次最佳分记录不存在时行锁不起作用 | 开局和结算共用事务内账号行锁，统一锁顺序 |
| 遮司嵌入页清空记录失效 | 沙箱禁止浏览器 `confirm()`，按钮无法完成清空 | 使用页面内确认对话框，默认聚焦取消；确认后只清空命格录 |
| 遮司证帝/仙统计出现 `NaN` | 等级统计漏初始化“帝”，总计相加后变成无效数字 | 补齐等级计数 |
| 开发依赖 `fast-uri` 的已知漏洞 | 开发工具链间接依赖 3.1.5 命中 4 条 URI 解析安全公告；不在生产运行依赖中 | 仅将该锁定依赖更新至 3.1.7 |

账号竞态需要特定并发时序，本轮没有发现实际被利用的证据。聊天室房间混入是前端隔离问题；不能据此认定服务端允许读取无权限的私聊。

## 仍需继续优化

1. **排行榜需要服务端验证赛局过程。** 当前分数公式、指标范围、用户归属和赛局有效期校验，不能证明浏览器上报的境界、击杀或消行真实发生过。应采用服务端生成种子、记录操作并重演结算，或直接服务端运行模拟。小游戏当前没有兑换正式资产的能力。
2. **遮司分难度排行。** 如履薄冰、爽玩和养成的概率与玩法不同，目前共用最佳分榜，不适合直接作同条件竞技比较。
3. **私聊已读请求。** 继续完善网络断开后已读回执的补传和去重。
4. **塔防内容与画面。** 当前地图固定为 12×8、3 波敌人、3 类塔。适合下一版扩充敌人差异、地图与波次，再增加角色移动、弹道和受击反馈；已有单角色、升级与暂停逻辑可以继续沿用。
5. **专用验收账号。** 生产还缺专用测试账号，无法自动覆盖真实 Cookie 登录、两账号加好友/私聊和成绩入榜的完整链路。现有自动测试不能替代这一项线上验收。

## 验证记录

- 线上 `/api/health/ready` 返回 ready，数据库检查为 ok；遮司页面仍返回单组 `SAMEORIGIN` 与 `frame-ancestors 'self'`。
- 从 GitHub 只读核对的发布分支仍为 `c362c2d`。
- `npm audit --registry=https://registry.npmjs.org`：修复后生产及开发依赖总计 0 个已知漏洞。默认 npmmirror 没有实现 audit 接口，因此本次明确使用 npm 官方 registry。
- Firefox 独立测试配置验证了实际 `allow-scripts allow-same-origin` 嵌入环境：对话框可打开，默认焦点在取消，取消保留记录，确认清空记录且保留成就，证帝/仙统计正确。
- Arcade 并发修复通过服务层回归核对事务内共同账号锁及锁定顺序；本地没有真实 PostgreSQL，因此本轮未执行真实数据库并发压测。
- 后端全量测试：90 个套件、443 项通过。
- 前端全量测试：102 个文件、483 项通过；新增交错时序回归覆盖账号切换、聊天室切换、断线重试、好友查询与小游戏重开。
- 共享包、后端及前端类型检查通过；共享包和后端构建通过，前端 community 生产模式构建通过。
- 最后的当前房间消息过滤与跨账号过期读取响应检查均已包含在最终生产构建中。
- `git diff --check` 通过；本轮没有新增数据库迁移。

检查结束时修复保留在本地，线上仍为检查基线 `c362c2d`。随后用户明确要求发布开发协作模块，本报告中的修复随该模块一起部署；最终线上版本为 `5f0f256`，完整发布与后续验证见 [2026-09-07 发布记录](./RELEASE_2026-09-07.md)。GitHub 同步尚未成功，不应把本地/线上版本写成已经推送。
