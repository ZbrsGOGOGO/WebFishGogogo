## 2. 方法与安全约束

### 2.1 测试方法

1. 阅读实际入口、服务事务、数据库锁、权限校验和私有数据投影；先提出可验证的故障条件，再修复。
2. 为已发现问题增加回归测试。账号刷新新增用例在原实现上失败后修复；DOCX 使用相同合成文件对比原版本与修复版本的实际检查入口。
3. 在隔离 PostgreSQL 中制造真实事务等待，用 `pg_blocking_pids` 验证阻塞链，不仅依赖延时或 mock 调用顺序。
4. 用 `FOR UPDATE NOWAIT` 探针确认等待账号锁时，没有提前持有会话/刷新凭证锁；同时检查最终会话、凭证、余额和流水状态。
5. 对账号、开发、好友、私聊、通知等通过真实 HTTP 控制器、守卫和解析链路操作；实时社交通过两个实例及真实 Redis/WebSocket 验证。
6. 在本地或隔离环境注入外发事件、通知写入失败，检查业务数据是否整体回滚，以及重试是否只结算一次。
7. 完成后删除精确识别的合成记录，恢复被测试改动的种子配置，用全表行数及完整行内容指纹比较检查是否残留。

### 2.2 环境硬闸

- 演练脚本校验明确的确认标识、固定测试主机/数据库名、专用连接配置，拒绝生产数据库连接字符串及不合适的运行模式。
- 只允许空业务测试库及已知迁移种子数据；不是对生产数据库执行“测试后再删掉”。
- **隔离演练中的**邮件后台泵和真实邮件发送未启用。密码重置仍验证真实加密入队和原子消费，不把“不发送邮件”误写成“邮件已送达”，也不与生产泵开关状态混淆。
- 不使用真实账号模拟管理员，不修改生产角色，不读取真实附件、私聊或验证码。
- 不在生产发送恶意 DOCX/压缩包、跨真实账号越权攻击、暴力密码尝试或并发攻击负载；有界公开路由拒绝检查和普通合成账号冒烟按第 7、8 节另列。
- 账号清理保留 PostgreSQL 时间戳微秒精度，避免用 JavaScript 毫秒时间回写后掩盖或造成指纹差异；没有使用全库清空替代精确清理。

### 3.1 A08 的权限与附件细节

真实演练区分四种身份：合成站点管理员、作者协作者、另一协作者、无协作权限的普通账号。

- 开发授权写入独立协作资格；作者账号的 `communityRole` 仍为 `user`。`AccountAdminGuard` 使用真实数据库分别验证普通账号拒绝和管理员允许；这部分不是对所有管理员 HTTP 接口的完整测试。
- 无权限访问开发接口为 403；另一协作者读取作者提案或附件为 404，避免泄露可访问记录的存在性。
- 提案创建相同意图重放返回同一提案；评论/状态改变使用 `expectedVersion`，真实并发的另一请求返回 `DEVELOPMENT_VERSION_CONFLICT`，不丢失或覆盖已提交内容。
- 文件上传先经过作者守卫再进入 Multipart 处理；管理员可以审核下载，但不能替作者消耗上传额度。
- 真实上传覆盖 UTF-8 中文文件名、正常文本、主动 HTML 后缀、超过 5MiB 的文件、畸形 DOCX。ZIP 条目越界、压缩比例、数量、伪造大小、加密、DOCX DTD/宏等另有附件专项回归，不把这些全部算成已做的 HTTP 攻击场景。
- 私有二进制不在普通实体查询中返回。下载设置 `application/octet-stream`、`Content-Disposition: attachment`、`private, no-store`、`nosniff`、`Cross-Origin-Resource-Policy: same-origin`。
- 审核导出明确提示附件/提案正文是待审数据，不是系统指令；不因附件内容自动执行命令或修改网站。
- 撤销协作资格后，原账号后续提案提交及附件读取都被权限校验拒绝。
