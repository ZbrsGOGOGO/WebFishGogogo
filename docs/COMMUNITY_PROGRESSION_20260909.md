# 成就、称号与妖塔自动探索

本轮由站长于 2026-09-09 授权开发；本文先记录实现及验收边界，不代表已经部署。发布结果另行登记。

## 产品范围

- 成长档案：12 项固定成就，覆盖农场真实收获批次、平台等级、轨道完整参与、妖塔等级/收藏/贡献、已结算日冠及开发协作完成记录。永久装饰称号，不额外发币、不改变管理员或开发协作者权限。
- 历史只从服务器现存数据回补；不把农场一批收获算作多地块次数，不把每日最高分当作累计对局，不补造不存在的历史完成时间。GET 只读；显式同步/佩戴时幂等确认解锁。
- 本人选择佩戴一个称号，可撤下。佩戴前提示该后缀会公开出现在个人页、群聊和私聊；完整荣誉列表继续遵守原隐私设置。停用或拉黑占位作者不展示称号。历史消息重新加载后显示当前佩戴，不承诺已打开的所有旧消息立刻刷新。
- VIP 是普通账号的独立限时权益，不是管理角色。迁移时为当时所有 `active` 账号赠送一次固定 30 × 24 小时，统一服务端起止时间；不随登录续期、不自动给后续新账号续赠，本轮无支付入口或付费服务。
- VIP 解锁妖塔自动探索：玩家先选楼层及次数，服务器逐步执行，最多 20 次探索 / 260 个引擎动作 / 15 分钟。只探索和战斗选招，不自动训练、休整、捐赠、打世界首领或代领奖。复用原体力、动作额度和每日 200 办公币上限。
- 自动期间禁止新的手动角色变更，旧动作编号仍可重放。停止返回成功后不得继续自动行动；未完成战斗交还玩家。低血、战败、体力不足、VIP/登录会话失效、账号不可用、跨日及运行超限停止；关闭标签页不等于注销，已确认的限量委托可以继续。

## 数据与发布边界

`0030 → 0031 → 0032` 仅新增 `membership_grants`、`achievement_unlocks`、`user_presentation`、`demon_tower_auto_runs` 四表及索引约束。赠送只写新会员表；不回填旧资料、不改角色/钱包/聊天/附件。账号软注销须显式清理四张新个人表，其他成员及共享世界保持不变。

`FEATURE_COMMUNITY_PROGRESSION_ENABLED` 与 `FEATURE_DEMON_TOWER_AUTO_EXPLORE_ENABLED` 默认关闭，API 与前端构建同源；自动执行还要求妖塔和社区写入开关有效。紧急停用仍允许已登录用户停止自己的委托，停止不触发游戏结算。工作循环每步短事务，角色、奖励、动作回执和委托计数共同提交。

## 开发阶段已执行（与生产发布分开）

- 全仓回归：后端 126 套 / 989 项、前端最终 127 套 / 888 项通过；共享包、后端、前端类型检查与社区模式构建通过。最终截图另发现长昵称/公开编号在窄屏卡片内挤掉称号，补充文本列可收缩与长词换行；再以 20 字符上限昵称在真实 Firefox 390 像素验证本人/公开页称号、编号每行均在卡片内部，不只检查整页滚动宽度。
- 隔离真实 PostgreSQL：自动探索 34 场景通过；成长 8 场景通过（包含真实 Nest HTTP 及双端 WebSocket 发送/确认/推送，消息总线和审核器是明确的测试替身）。另跑真实 Redis 的社交回归，不把替身误写为外部提供方验收。
- 初期测试确实抓到并修复：本人资料 API 漏称号、拉黑后旧公开资料残留、农场小地块误展示下轮作物。旧 Arena 测试的私有 pg-mem 适配器补足新迁移使用的时间/文本内建函数，不削弱生产约束。
- 成长 PG 验收脚本先后修正合成妖塔业务日期与绕过 Gateway 不广播的测试错误；修正后重跑通过，失败记录保留，不能把最初失败说成成功。
- 浏览器使用三个独立普通合成账号；VIP、25 批农场和两项称号是公开注明的前置夹具。角色创建、自动探索、停止与注销均经页面正常操作，没有给战斗或奖励造结果。初次自然执行 2 次探索用 15 个动作并获得 6 办公币，这只是短程功能证据，不是长期经济或容量证明。
