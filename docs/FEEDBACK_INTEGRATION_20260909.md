## 协作完整性

- 列表与详情显示同一份可信审计投影。贡献者文本、任意 JSON、损坏审计或未来版本不能伪造完成项或吞掉跟进提示。
- 所有者一次最多维护 40 个验收项；仅按既有 owner 权限和请求版本保存，锁内重新授权。保存清单不自动关闭整条提案。
- 默认页面“全部状态”导出包括已完成条目、全部评论、分项进度和附件预览；使用 PostgreSQL `REPEATABLE READ` 保证一次快照一致。
- 单次上限 200 条，超过明确拒绝，不返回半份文件冒称完整；附件预览可能截断，必须另读原件。旧 API 未显式传状态时仍保持待审/待补充范围。
- 运行在本地内存数据库的测试只能验证流程，不能验证并发快照隔离。真实 PostgreSQL 双连接验收另记。
- 发布后使用独立运维 CLI 回填实际范围：精确 ID、版本、全长已验收提交与确认串，作者→请求锁、CAS、审计、内容指纹幂等、一次通知。该脚本不通过 HTTP 暴露，不冒充站长，不执行附件、授予角色或自动部署。未完成提案进入实现中，旧已完成审计保留且显示剩余项。

## 老数据和上线边界

- 本批没有 SQL 迁移：schema32、33 条登记、136 张业务表继续保留；不重建 PostgreSQL/Redis/网关，不删除数据卷，不重放赠送 VIP。
- 妖塔 JSON 的成长规则版本升级不等于旧引擎可安全继续写。GET 不迁移存档，旧战斗/旧托管战斗结束后才在合法动作中适配，保留既有装备和资产。
- 生产回退基线为 `727576bb8312889da3eae0795995848da787dc95`。回退前须停止当前 API 接收/完成在途动作，在启动旧 API 前关闭 `FEATURE_COMMUNITY_DEMON_TOWER_ENABLED` 和 `FEATURE_DEMON_TOWER_AUTO_EXPLORE_ENABLED`。旧前端入口与只读投影可能仍可见，但写接口暂不可用，旧投影也不保证正确表达新成长机制；不得让旧引擎继续写新存档。
- 不回灌旧数据库、不清除 growth、不回收办公币或真实用户数据；应尽快以前向兼容修复恢复妖塔服务。其他功能不因回退额外扩大权限。
- 发布只改镜像标签，不修改已有权限、支付/邮件配置或赠送周期。先完整恢复验证新鲜加密备份并做异机校验，再仅更新 API/Web。
