# 九层妖塔源码版候选：整体替换边界

本页描述 2026-10-16 待发布的九层妖塔源码版候选。它以站长在实验室 5090 上提供的最新 `jiuceng.zip` 为唯一玩法源，ZIP SHA-256 为 `2fe1c88e998f740ad01e8722a2e2c06f58c5eff41824c3aee833bd8b0e76bd2c`，附件内源码提交为 `d87e2df254397e0ce1bb2b9dac5f99567bc94ee6`。候选尚未完成生产切换，提交、镜像、部署时间和线上验收结果均以[候选发布清单](RELEASE_DEMON_TOWER_SOURCE_20261016.md)中的实际回填为准。

## 产品边界

- `/games/demon-tower` 在候选切换后只加载该 ZIP 的浏览器玩法；这是完整替换，不是把新旧界面、规则、存档或经济融合。旧 React 妖塔、旧排行榜和旧自动探索不再进入活动路由或 Nest 运行模块。
- 角色、装备、功法、打造、探索、好友切磋和九层世界规则来自该 ZIP。本站适配仅负责账号联网存档、安全隔离、真实好友边界、共享世界原子写入、深浅色和窄屏可用性。
- “塔内办公币”是源码玩法自己的存档字段，与网站办公币、钱包、期权持有者身份和全站成就完全隔离。源码版榜单不发网站奖励。
- 新源码存档不迁移、拼接或回退读取旧妖塔存档；第一次进入会建立一份独立新档。旧数据和旧源码只保留作发布回滚及历史审计，不参与当前计算。
- 期权持有者保留期限和爱发电支持台账，但不再附带旧自动探索或其他玩法特权。旧妖塔成就不再新增，已经实际写入的历史称号继续保留并可佩戴。

## 运行与数据隔离

源码运行在没有 `allow-same-origin` 的 sandbox iframe 中，只允许脚本和游戏弹窗。iframe 不能读取网站 Cookie、访问令牌、父页面 DOM 或浏览器同源存储，也不能直接联网。父页面只接受来自当前 iframe 窗口、`origin=null`、本次随机 nonce 和严格白名单格式的消息。

父页面使用当前登录会话调用 `/api/v1/games/demon-tower/source/*`。服务端使用五张独立表：

- `demon_tower_source_profiles`：当前账号的不透明玩法存档和最小排名投影；
- `demon_tower_source_world_floors`：九层共享世界；
- `demon_tower_source_contributions`：共享世界展示贡献；
- `demon_tower_source_daily_actions`：服务器日限额；
- `demon_tower_source_commands`：三类共享世界动作的短期幂等回执；普通存档最近一次回执随个人档案保存，避免每次自动保存永久新增命令行。

迁移 `1700000000042-AddDemonTowerSource` 只新增上述五表和九层种子：生产切换前基线为 schema42 / 42 条迁移 / 151 张 public 表，候选升级目标为 **schema43 / 43 条迁移 / 156 张 public 表**。迁移不更新、删除或改造历史 `demon_tower_*` 表；旧表和旧存档冻结，只用于回滚与审计。

普通存档采用账号锁、期望档案版本和请求幂等。每个解码后的存档最大 512 KiB，结构深度、节点、数组和字符串总量另有限制；每个账号按北京时间自然日最多 **720 次存档**、累计 **64 MiB 解码存档写入**。共享世界有 `damage`（首领伤害）、`channel`（通道建设）、`clue`（探索线索）三种写动作：伤害采用与客户端战力无关的固定服务端上限，三类合计每账号每日最多 **120 次共享世界动作**。探索发现线索时，线索、个人探索后的存档、额度、贡献与世界版本一起提交，刷新后以云档和世界回执恢复。因为玩法引擎来自隔离浏览器，服务端不重演整场随机战斗或探索，这三类属于有服务端限额、版本、事务和幂等保护的客户端申报；因此共享数据只作玩法展示，不接网站钱包、成就或权益。

每个全服动作必须同时携带 `requestId`、`expectedVersion` 和动作后的 `saveData`。服务端在一次数据库事务内原子更新账号档案、每日额度、世界层、贡献和命令回执；相同请求只返回既有回执，不重复扣额度或执行伤害、建设、线索。客户端只对同一逻辑请求复用同一请求号；如果网络结果仍不确定，会冻结后续写入并要求整页重载，以服务端档案和回执重新建立状态，不重新掷随机结果。

只有 `PUT /source/progress` 与三个世界写接口 `POST /source/world/damage|channel|clue` 使用精确的 Nginx `client_max_body_size 1200k` 和 Nest JSON `1200kb` 解析边界，以容纳最坏情况下被 JSON 转义的 512 KiB 存档；其余旧妖塔路由仍保持 20k/默认小请求边界。1200k 只是传输包络上限，不能绕过服务端对解码存档 512 KiB 的权威校验。

好友列表仅使用仍有效的双向好友关系，并排除任一方向的拉黑。好友战斗只返回服务端裁剪的等级、五维、丹药、命格和天赋投影，不返回对方完整存档。账号注销会删除该账号的源码存档、命令、每日额度和贡献身份；匿名共享世界状态保留。

## 旧功能退役

- 旧 `/api/v1/games/demon-tower/catalog|overview|actions|leaderboard|contributions|auto-explore` 只返回 410 或认证拒绝，不再执行玩法。
- 旧 `DemonTowerService`、奖励 worker 和自动探索 worker 不在 `DemonTowerModule` 注册。
- 生产 Compose 和构建门禁把旧自动探索、旧扩展引擎强制为 `false`，环境中残留 `true` 会使预检失败。
- 压力整理不再生成或领取妖塔材料/研习册，原 0.3% 权重明确并入解压币；旧类型只为无损读取历史记录保留，不写入新旧妖塔。
- 切换必须避开北京时间跨日窗口：先让旧 worker 补齐并核对所有历史贡献日，随后停止旧 API 和旧奖励 worker、等待在途写入排空并确认切换日伤害快照稳定，最后才允许用日期绑定且不暴露 HTTP 的脚本结算当前切换日，核对合格冠军恰好一笔奖项、奖励凭证和钱包账本，或明确证明当日没有合格记录。不得先结算再继续接受旧伤害；候选文档不声称该步骤已经在生产执行。

## 回滚边界

- 应用回滚只切 API/Web，保留 schema43、五张源码表以及切换后的全部新旧数据；禁止运行 DOWN、删除新表或用切换前数据库备份覆盖生产。
- 0042 的 DOWN 只允许用于尚无任何玩家/命令/额度/贡献、九层世界仍与初始种子完全一致的隔离演练；一旦有新档或世界变化即主动拒绝，避免误操作删档。
- 旧 API 不理解五张源码表的账号注销清理。回滚到旧 API 前必须设置 `FEATURE_ACCOUNT_DELETION_ENABLED=false`，并同时验证前端注销入口不可用、注销 API 被服务端拒绝；任一项未满足都不能宣称回滚安全。
- 回滚期间源码版写入不可用是可接受的降级，恢复候选应用后继续读取原新档；不得把旧存档转换、拼接或写回源码版。
