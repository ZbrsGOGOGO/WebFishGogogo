### 3.2 持续验证命令

测试数量会随功能增长，不在文档中写死。每轮合入以这些命令为准：

```bash
npm run build:shared
npm run typecheck
npm test
npm run build
```

高风险资产流程还应覆盖：

- 签到重复请求不重复发奖；
- 种植/收获重试不重复扣除或收获；
- 未成熟作物不能提前收获；
- 用户不能操作他人土地或战斗记录；
- 相同战斗快照、种子和引擎版本得到相同战果；
- Outbox 重试不重复记录活动或推进任务；
- 客户端不能通过自报时长、重复序号、隐藏页面或断档心跳加速完成阅读任务；
- 每日任务重复领奖不重复发放资产；
- 后端连续构建均能生成可启动产物。

| 跨系统联动 | ✅ | 签到、有效阅读、农场和竞技场均通过可信事件接入任务与最近活动 |
| Redis | ⬜ | 缓存、限流和队列；不得作为用户资产真源 |
| 可观测性 | ⬜ | 请求 ID、结构化日志、指标、告警与审计 |
| 发布自动化 | 🚧 | 预检与备份/恢复脚本已实现；灰度、深度健康检查、自动回滚仍待实机阶段 |

优先顺序建议：

1. 完成目标服务器部署与备份恢复验证；
2. 补齐请求 ID、结构化日志、指标与 Worker 告警；
3. 扩展任务配置、周期任务与运营能力；
4. 根据实际流量再引入 Redis、队列或独立 Worker 扩容；
5. 最后再考虑排位、赛季、社区、会员等非首期能力。

## 五、合规与上线边界

- 阅读内容必须由用户自己合法拥有，不建设盗版内容库或公共分发入口。
- 游戏不提供赌博、博彩、现金返佣、付费概率博弈或虚拟资产提现/转让。
- 不复制第三方游戏的名称、角色、图像、技能与文案。
- 对外使用“工作模式/隐私模式”等中性描述。
- 正式上线前替换示例备案号，完成适用的 ICP 备案和隐私/条款复核。
- 生产环境必须使用独立强 JWT 密钥和数据库密码，文档卷必须纳入异机备份。
