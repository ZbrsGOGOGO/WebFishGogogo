# 《摸鱼升职记》工位塔防 V1

- 站点名称：摸摸公司
- 游戏正式名：摸鱼升职记
- 主玩法：工位塔防
- 文档状态：V1 开发与验收基线
- 版本状态：待部署
- 更新日期：2026-09-04

## 1. 版本目标

V1 只验证一个简短、完整、可重复游玩的工位塔防闭环：玩家操作一名工位守卫，在固定工位地图上建造三类办公用品塔，完成三波防守并获得本局分数。

当前实现是纯浏览器游戏。它不是服务端成长系统，不得以“已上线”、“可跨端存档”或“可获得社区资产”对外描述。

## 2. V1 产品范围

### 2.1 本期必须有

- 一名且始终只有一名玩家角色。
- 三类职责不同的办公用品塔。
- 三波逐步增压的敌人。
- 角色移动、自动攻击和一个主动技能。
- 建造、升级、出售、开始波次、暂停/继续和重新开始。
- 基地生命、局内资源、分数、最高分、胜利和失败反馈。
- 键盘和移动端触摸操作。

### 2.2 本期明确不做

- 服务端存档或多端同步。
- 服务端排行榜或 Arcade 排行榜接入。
- PVP、好友挑战、帮派或公司社交联动。
- 正式办公币、经验、体力、装备、道具或概率掉落。
- 放置挂机、离线收菜、升职职级和长线数值成长。
- 付费、充值、交易、提现或可兑换奖励。

放置离线、摸鱼升职和公司社交是《摸鱼升职记》的长期产品方向，但不是当前 V1 的完成项。

## 3. 单局流程

1. 进入游戏后查看地图、工位守卫、基地生命、局内资源和第一波信息。
2. 点击空塔位，从三类办公用品塔中选择一类建造。
3. 主动开始当前波次；敌人沿固定路线向基地前进。
4. 工位守卫和防御塔自动攻击；玩家可移动角色、释放主动技能，并在可操作阶段升级或出售塔。
5. 消灭当前波全部敌人后进入下一波准备；敌人到达终点时扣除基地生命。
6. 完成第三波则胜利；基地生命归零则失败。
7. 结算时展示本局分数及本机最高分，玩家可以立即重开。

## 4. 唯一角色：工位守卫

- 地图上的玩家角色固定为“工位守卫”。
- 登录用户显示为“用户昵称 · 工位守卫”；头像只影响视觉表现，不改变数值。
- 未登录或无可用昵称时可使用“游客同事 · 工位守卫”等明确的游客标识，但不创建另一个角色。
- 角色使用 WASD 或方向键移动，并自动攻击范围内最合适的敌人。
- 按 Space 释放“专注脉冲”；技能冷却期间不可重复触发，界面必须告知可用或冷却状态。
- 玩家可使用局内资源升级这同一名守卫；升级改变属性，不新增队员或伴随角色。
- 任意可玩时刻的玩家角色数量必须恒等于 1；防御塔、敌人、特效和用户头像都不得被计为第二名玩家角色。

## 5. 三类办公用品塔

| 防御塔 | 定位 | 必要行为 |
|---|---|---|
| 订书机 | 单体输出 | 稳定攻击单个范围内敌人，用于处理高优先级目标 |
| 咖啡机 | 减速控制 | 造成伤害并在有限时间内降低目标移动速度，减速不可永久残留 |
| 打印机 | 范围输出 | 对命中位置附近的多个敌人造成伤害，用于处理密集目标 |

通用规则：

- 只能在显式塔位上建造，已占用塔位不能重复建造。
- 建造和升级前必须验证局内资源；不足时不扣费、不改变塔状态。
- 出售必须移除目标塔并一次性返还界面所示的局内资源，不得重复结算。
- 升级后的属性变化必须可预期，不得依赖未公开的付费、概率或服务端数据。

## 6. 三波敌人

| 波次 | 主题 | 数量 | 产品意图 |
|---:|---|---:|---|
| 1 | 零散待办 | 5 | 让玩家理解路线、建塔和角色攻击 |
| 2 | 催办邮件 | 7 | 要求玩家组合单体、减速与范围能力 |
| 3 | 会议风暴 | 9 | 最后一只为高生命首领，验证阵型与主动技能 |

- 波次开始必须由玩家明确触发，页面初次加载不自动出怪。
- 本波敌人未清空时不得重复开启同一波或跳过到下一波。
- 胜利或失败后停止生成敌人、移动、攻击和重复结算。

## 7. 操作、可访问性与响应式

### 7.1 桌面端

- WASD 和方向键都可移动工位守卫。
- Space 可释放主动技能，但在表单控件中输入时不得误触游戏快捷键。
- P 或 Esc 可暂停/继续对局，同时仍保留可聚焦的界面按钮。
- 建造、升级、出售、开始波次、暂停和重开都必须有可聚焦的按钮，不得只依赖画布坐标点击。

### 7.2 移动端

- 不依赖物理键盘；角色移动和主动技能必须有触摸控件。
- 在 360px 宽度下不应出现阻断核心操作的水平滚动、重叠或裁切。
- 塔位、建造选项和局内主操作应保持可辨认的触摸区域。

### 7.3 状态反馈

- 生命、资源、波次、分数、技能冷却、暂停、胜利和失败不得只用颜色表达。
- 非法或资源不足的操作应保持原状态，并给出可理解的文字反馈。
- 暂停后，敌人移动、角色与塔的攻击、敌人生成和技能冷却都不应继续推进。

## 8. 本机存储与数据边界

V1 的唯一持久化键为：

```text
momo.workstation-tower-defense.settings.v1
```

值只包含：

```json
{
  "bestScore": 0
}
```

约束：

- `bestScore` 只能是有限、非负整数；损坏、缺失或越界值按安全默认值处理。
- 只在本局分数大于历史最高分时更新。
- 不保存当前波次、基地生命、局内资源、角色位置、敌人、防御塔、冷却或结算奖励。
- 本机最高分不上传、不进入服务端排行榜、不能兑换账号资产。
- 浏览器禁用存储或写入失败时，当前单局仍应可玩，只是无法跨刷新保存最高分。

## 9. 历史乐斗兼容与数据保护

工位塔防是新玩法，不是对旧乐斗字段、奖励或战报的换皮重用。

- `OfficeBattleModule` 从当前 `CommunityAppModule` 卸载，社区 API 不再提供旧 `/api/v1/games/office-battle` 业务。
- 旧模块源码、实体、迁移及 11 张 `office_battle_*` 表保留，本版本不重命、不删表、不清空、不转换。
- 旧角色、职业、装备、战报、排行、待领奖励、资产流水和既有账户余额只读保留。
- 旧本机键 `zbrs.office-battle.profile.v1` 原样保留，工位塔防不读取、不删除、不自动导入。
- 旧数据不换算为塔防最高分，塔防成绩也不反向写入乐斗、统一经验或钱包。
- `/tower-defense` 是当前标准路由；`/ledou` 和 `/battle` 只作兼容跳转，不再渲染旧玩法。

## 10. 验收清单

### 10.1 玩法

- [ ] 页面进入可玩状态后，地图上始终恰好一名工位守卫。
- [ ] 键盘和移动端控件均可移动角色，角色会自动攻击。
- [ ] 专注脉冲可触发，冷却中不能连续生效。
- [ ] 三类塔的单体、减速和范围差异在实际战斗中可观察。
- [ ] 建造、升级、出售和资源不足边界都有正确结果，资源从不为负。
- [ ] 三波只按顺序开启，第三波有高生命首领。
- [ ] 清空第三波进入胜利，基地生命归零进入失败，结算只发生一次。
- [ ] 暂停时游戏世界不推进，重开后无上一局敌人、塔、计时器或技能状态残留。

### 10.2 存储与服务边界

- [ ] 刷新后只恢复最高分，不恢复上一局进度。
- [ ] 损坏的本地存档不导致白屏、NaN、负分或资源异常。
- [ ] 页面与静态资源加载完成后断网，当前单局仍可继续，游戏过程不请求塔防、乐斗、统一资产或排行榜 API。
- [ ] 玩一局前后，旧 `office_battle_*` 数据、统一经验、办公币和旧本机存档均不变。
- [ ] 社区应用不装配 `OfficeBattleModule`，且 `FEATURE_COMMUNITY_BATTLE_ENABLED` 不能使旧页面在新版本中复活。

### 10.3 路由、响应式与回归

- [ ] 公开模式可直接打开 `/tower-defense`；社区模式在按现有登录守卫完成鉴权后打开同一游戏。
- [ ] `/ledou` 和 `/battle` 最终显示同一个新游戏，而不是旧乐斗页面。
- [ ] 360px 移动端尺寸可完成建塔、移动、技能、开波、暂停和重开。
- [ ] 关键状态具有文字或语义标记，不只依赖颜色、动画或音效。
- [ ] `npm run verify` 通过，新增游戏引擎、页面、路由和数据边界测试全部通过。
- [ ] 部署后的 HTTP 烟测、桌面真机和手机尺寸验收通过，再修改“待部署”状态。

## 11. 后续路线

### 11.1 服务端存档

如果需要跨设备保存，应为工位塔防新建独立、追加式 schema 和 API。不改名、复用或覆盖 `office_battle_*` 表，不将浏览器最高分自动导入正式资产。

### 11.2 排行榜

排行榜只能使用服务端可验证的对局。不直接接收客户端自报的 `bestScore`；需先设计幂等结算、版本化规则、异常成绩处理和排行榜重算机制。

### 11.3 长线产品

放置离线收菜、升职、部门/公司社交和长线经济必须分别完成服务端权威结算、防作弊、隐私、内容治理和运营验收。在这些条件满足前，它们只是路线图，不是 V1 能力。
