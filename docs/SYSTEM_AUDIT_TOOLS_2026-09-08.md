# 2026-09-08 本机工具真实 Firefox 验收

本文补充[系统主报告](SYSTEM_AUDIT_2026-09-08.md)和[全站浏览器报告](SYSTEM_AUDIT_UI_2026-09-08.md)，记录实际输入、按钮操作与结果，不把“页面能打开”作为工具计算正确的证据。

## 环境与范围

- 使用已有隔离 Firefox 会话 a/b，通过本地测试入口 http://127.0.0.1:4488 操作；控制接口仅监听本机 4489。没有操作用户个人浏览器、登录真实账号或向生产写入。
- 浏览器实际报告 Firefox 154.0，Ubuntu/Linux；a 为 1440 宽，b 为 390 宽。JSON、颜色和文本在 390 宽度操作，实测页面 scrollWidth 为 390，没有横向溢出。
- 基线静态产物来自生产 0ec2d0b，目录为 /tmp/webfish-full-audit.bmEyRd/web-baseline。本轮修复后，将本地代理切到新构建的 packages/frontend/dist，清理测试会话并重新导航，复测计时器；随后在新构建补测余下 6 款工具。此处“修复后”是本地构建验证，不冒充最终镜像或生产验收。
- 所有输入/按钮均由 WebDriver 原生输入、点击或键盘 actions 执行。页面脚本只读取 DOM、浏览器时钟和资源记录，没有注入转换结果、修改 React 状态或伪造时间流逝。
- 公开目录实际有 11 款工具。本次先对计算、格式化、已有编码表示转换、计时和文本整理 5 款工具深入操作，随后补齐其余 6 款；11 款均实际完成至少一条正常输入→结果流程，并检查适用的非法/空值与恢复，不等于穷举全部功能组合。
- 当前没有 Base64、URL 编解码工具。“编码”覆盖现有 JSON 的 Unicode 转义解码和颜色 HEX/RGB/HSL 表示转换，不宣称通用编解码功能已经存在。

### JSON 格式化、校验和 Unicode 转义

输入：

~~~json
{"company":"\u6478\u6478\u516c\u53f8","text":"中文","n":2,"items":[1,true]}
~~~

| 原生操作 | 实际结果 |
| --- | --- |
| 点击“格式化” | 输出两空格缩进；company 为“摸摸公司”，text 保留“中文”，数组和布尔类型正确 |
| 点击“压缩” | 输出 {"company":"摸摸公司","text":"中文","n":2,"items":[1,true]} |
| 点击“校验” | 输出“JSON 合法 ✓” |
| 输入 {"items":[1,]} 后格式化 | 明确提示“JSON 格式有误，请检查第 1 行、第 13 列附近。”，旧输出清空，输入框 aria-invalid=true；页面仍可操作 |
| 清空后点击格式化 | 显示“请输入 JSON 内容” |
| 错误后输入 {"ok":true} 并压缩 | 输出 {"ok":true}，恢复正常 |

Unicode 转义测试验证的是现有 JSON 解析与序列化语义，不是新增独立编码器。证据：tools-json-unicode-mobile.png、tools-json-invalid-mobile.png。

## 计时器：发现、修复及真实复验

### 已复现的原有缺陷

1. 在倒计时分钟数输入合法值 1，显示 00:01:00。
2. 点击“☕ 休息 5 分钟”：显示变为 00:05:00，但分钟输入仍为 1。
3. 点击正计时，再切回倒计时：恢复为旧的 00:01:00，而不是刚选择的 5 分钟。
4. 专注 25 分钟同样不同步。非法值 -1 后选择预设，也会出现显示 25 分钟但输入仍 -1 的矛盾。

原因是 Timer.applyCountdown 更新了 durationMs，却未同步 minutesInput。经主代理明确授权，本轮仅在预设处理函数增加输入同步，没有新增工具功能或修改计时/经济规则。

基线证据：tools-timer-normal-preset-mismatch.png、tools-timer-preset.png。

### 修复后真实 Firefox 操作

| 操作 | 实际结果 |
| --- | --- |
| 合法 1 分钟→休息 5 分钟 | 输入 5，显示 00:05:00 |
| 正计时→倒计时往返 | 仍为输入 5、00:05:00 |
| 合法 1 分钟→专注 25 分钟 | 输入 25，显示 00:25:00 |
| 正计时→倒计时往返 | 仍为输入 25、00:25:00 |
| 输入 0.05 分钟并开始，真实等待约 3 秒 | 显示归零，按钮自动恢复“开始”，不显示负数 |
| 输入 -1 后选择休息预设 | 输入变为 5，浏览器 validity.valid=true，显示 00:05:00 |
| 5 分钟开始、等待到 00:04:58 后暂停，再真实等 1.5 秒 | 显示仍为 00:04:58 |
| 继续计时 | 显示继续到 00:04:57 |
| 点击重置 | 恢复 00:05:00，分钟输入仍为 5，计时停止 |

基线另实际验证正计时 00:00:02→暂停等待 2 秒不变→继续 00:00:03→重置归零。负分钟输入显示零、保留浏览器 rangeUnderflow 校验，没有白屏。本次没有新增非法值提示文案。

修复后证据：tools-timer-presets-fixed.png、tools-timer-paused-reset-fixed.png。计时页本次资源记录没有 /api/ 请求。
