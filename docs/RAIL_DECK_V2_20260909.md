# 轨道难题：51 张牌库 V2 与兼容边界

本轮按站点所有者确认的补充开发范围，替换《轨道难题》后端正式牌池。实现和测试不代表已经部署；线上版本以最终发布记录为准。

## 真实数据来源与版本

- 本项目的轨道牌池在 `packages/backend/src/modules/community/rail/cards.ts`，由服务器引擎发牌，不是 Prisma seed 或独立的牌库数据库表。
- 新模板精确为善牌 19、恶牌 18、条件牌 14，共 51 张，类内/全局标题及模板 ID 均唯一。没有用旧词条填补数量，也没有保留第二个混合抽牌池。
- 牌池版本为 `rail-deck-20260909-v2`；稳定模板 ID 为 `rail-v2-good-01` 等显式编号。模板 ID 与 `r回合:p座位:类型:位置` 的卡牌实例 ID 分离，防止不同玩家拿到同一模板时互相出牌或覆盖卡牌。
- 新牌的 `templateId`、`deckVersion` 随牌面落入已有房间 JSON；每回合状态记录本回合真正发出的 `deckVersion`，公开投影仍只显示本人的手牌和已打出的牌，不公开他人暗牌或随机种子。
- 元数据为可选字段，因此不要求历史存档回填。没有新增数据库迁移、清空牌库表、删除房间/历史手牌或修改 seed。51 是正式 TypeScript 模板数量，不冒称数据库中已插入 51 行。

## 本轮牌文处理

51 条编号牌面中，48 条标题按对应编号清单原样保留，包括一般非图形虚构黑色幽默、神话/虚构人物、公众人物和超自然情境。没有为了统一温和风格而整批重写。

仅以下三项改成行为明确的虚构角色，不再把整个国籍群体、染色体特征或疾病本身定义为恶人：

| 模板 | 原设定问题 | 实际上线候选标题 | 调整范围 |
| --- | --- | --- | --- |
| `rail-v2-bad-05` | 将日本岛上全部人口按国籍/地域整体归入恶人 | 盘踞虚构岛屿、绑架旅人的海盗团伙 | 保留岛屿与群体规模的辩论情境，改以绑架行为界定虚构反派，不指向现实国籍群体 |
| `rail-v2-bad-11` | 将“超雄”标签与未来校园暴力直接关联 | 一个计划把学校当成靶场的歹徒 | 保留明确的虚构危害计划，移除染色体特征与必然暴力的错误绑定 |
| `rail-v2-bad-17` | 将帕金森病况本身作为食堂角色归恶的理由 | 故意克扣饭菜还把餐费据为己有的食堂阿姨 | 保留食堂角色，改为故意侵占餐费的具体行为，不污名化病患 |

条件牌 03 使用编号清单中的“你会爱上Ta”，不采纳后段说明中将 `T a` 打散的排版变体。其余编号标题不截断、自动纠错或增加新的恶行。

所有角色牌描述说明这是本轮虚构设定，不构成现实人物事实指控；条件牌说明其只改变辩论情境。诸如“身价增加”“送邮轮”“超能力”不触发钱款、办公币或数值技能结算。公众人物与条件牌随机组合仍是虚构游戏，不作为现实新闻或事实展示。

本公开说明仅记录必要的差异与机制，不包含私有反馈全文、作者身份、内部反馈 ID、附件、删除指令或服务器数据。

## 已有对局不改，新回合使用新池

1. 发牌时已把完整标题、描述和实例 ID 存入房间 JSON；出牌和加条件直接取玩家已有手牌，不通过新模板目录重新解释旧牌。
2. 旧回合缺少版本字段时，GET/投影不会补写新版本，也不修改其手牌或已放到轨道的牌。正常的超时托管仍按原手牌出牌，不因换牌池改变牌文。
3. 只有 `startRound` 真正开始下一回合时才换为 V2 并重新发牌。手动下一回合与合法超时跨回合均如此，旧评分历史保留。
4. 部署前已创建但未开始的房间，没有预发牌或牌池字段；部署后普通开始流程直接用 V2，不需要重建房间。
5. 仍支持 3–9 席，每名非列车长每类拿 3 张。原规则是每人独立洗牌，所以同一模板可在不同玩家手中出现；单手牌类内不重复，卡牌实例 ID 全场不重复。14 张条件牌足够每个人分别抽 3 张，不更改为会耗尽的公共牌堆。

- 精确数量、稳定 ID、标题唯一性、51 模板不可变、完整有界牌文和无 HTML/控制字符。

- `RailService` 使用实际实体及 SQL 的 pg-mem 集成测试：旧 waiting 房可开始、重复 GET 保留旧手牌/轨道、新回合通过正常命令 ID/顺序进入并使用 V2。此测试不冒充生产 PostgreSQL 并发锁测试或生产用户对局。
- 现有引擎回归保留，仅将旧“各类至少 24 张”的过时断言改成准确的 19/18/14；标题检查允许完整新牌文而非截断到旧 20 字。
