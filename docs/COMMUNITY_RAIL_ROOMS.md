# 轨道难题与房间密码

## 玩法和入口

从小游戏专区或玩家建房区进入 `/games/rail`；侧栏排行榜专区有独立 `/games/rail/leaderboard` 生存率日榜。原六款游戏继续共用各自单机/多人榜，轨道难题使用独立规则和数据表，不改原遮司存档或经典本机玩法。

- 3–9 个席位，每人按座次当一次列车长，其余人随机平衡分成 A/B 两队。
- 每轮各取 3 善、3 恶、3 特性手牌，善牌放己方、恶牌放对方，再给任意尚未加特性的已出角色牌加一张特性。牌名、文案和界面均为本站原创，非血腥表现。
- 列车长选择经过的轨道，另一队计一次生存；自己的列车长轮不计生存率分母。其余成员评 1–10 恶魔值，禁止自评，最高值只用于趣味评选。
- 房主可在开局前调整 AI01–AI08 补位，至少保留一位真人；变更补位会重置准备。人机练习直接开局，不进入公开大厅。
- 真人建房支持最多 20 位观众中途进入，不占玩家席位。参与者仅有自己的手牌，观众没有任何人的未出手牌、随机种子或未来抽牌。
- 玩家与观众分开写入两个聊天频道，但房间成员可查看两个频道。最近 200 条为展示窗口，每页最多 50 条；双频道约每 1.2 秒刷新，撤回会清空正文，不承诺删除全部历史数据库记录。未通过审核的消息不发布，退出后不能继续读写房内讨论。
- 每轮出牌/特性/决策/评分/轮间展示分别最多 60/45/45/30/15 秒；超时合法代打，真人超时评分记弃评而非伪造投票。9 人一局最长 29 分 15 秒。

界面为静音、低饱和度工作台，支持手机快捷定位；Esc 便签遮罩保留当前选择和页面，不暂停服务器计时，也不隐藏网络活动。

## 日榜和办公币

每天北京时间 00:05 起结算前一天，轨道难题日榜第一名奖励 **100 办公币**，通过原钱包账本到账并发送通知，同一天只发一次，失败事务可重试。原六款各 100 的额度保持不变，新增轨道榜使全部七个冠军奖励理论上限为 700 办公币/日。

仅开局至少 3 位真人且没有机器人、个人完整完成每轮必要动作并未退出的建房对局可上奖励榜。按服务端最终生存率取当日最佳，同率保留最早达成时间，再按稳定账号标识排序。成绩归入服务器实际处理终局的北京时间日期。人机局、练习、观战、任一必要动作超时或退出都不发本榜奖励；恶魔值不参与奖励排名。同账号只能同时参加一个进行中的游戏房间，观战不占原六款的参赛位置。

个人累计只记录完整手动完成的对局，可包含练习；累计恶魔值与 MVP 是展示统计，不兑换货币。账户注销完成时清理该模块私人聊天正文、快照旧姓名和个人统计，保留他人的对局内容与已结算奖励账本。

## 用密码加入，取消新邀请码

新建的七款玩家房间都可在大厅发现，房主可选设密码；留空公开，设置后玩家和观众均须验证。密码采用 NFC 规范化，4–64 个 Unicode 字符，拒绝控制字符。服务端使用带密钥预哈希及 bcrypt 校验值，避免 Unicode 超过 bcrypt 72 字节被截断；不向客户端、日志或 Git 返回密码/校验值。

房主仅能在等待阶段修改或清除密码，需要当前版本；已加入成员无需重复输入。错误密码按账号与房间持久限速，密码在校验与加入间变化时拒绝加入。以前的私密邀请码房间不会被自动公开或改写，新界面不再生成或显示邀请码；历史房间已有成员可继续返回，旧接口兼容只为既有房间保留。

## 发布与回退

迁移 `1700000000029` 只新增 7 张轨道表及 `play_rooms.password_hash` 可空字段，不回填或修改原用户、钱包、聊天和存档。生产仅更新 API/Web、运行增量迁移；发布前必须完成加密完整备份、异机校验、真实 PostgreSQL 并发测试与还原副本 `0028 → 0029 → 0028 → 0029` 数据指纹验证。生产应用回退保留新表和密码字段，绝不执行迁移 down。

**旧版本不识别房间密码，禁止直接恢复旧版写服务。** 如回退到 `668d0db`，必须先设置 `FEATURE_COMMUNITY_WRITES_ENABLED=false`，以只读维护状态启旧 API，防止旧入房接口绕过新密码；直到密码感知版本重新上线并验收，才可重新开放写操作。仅保留数据库密码字段并不能保护旧程序。

微博、知乎站内热榜因无官方访问权限，所有者本次明确暂不接入；保留现有官方榜单链接，没有抓取或绕过上游限制。
